VTA 블록 GEMM 시뮬레이터

DRAM 메인 메모리 · #n = 엔트리 번호(메모리 순서)

버퍼에 올라간 적 있음 지금 버퍼에 있음 계산 완료 지금 사용 중 ×n = DRAM에서 n번 읽음

엔트리 하나는 메모리에 연속으로 놓여 있어서 DMA가 통째로 가져간다. 엔트리 번호는 W(j,k) = j×4 + k, X(b,k) = b×4 + k 순서다.

온칩 버퍼 SRAM

inp_ 입력 버퍼

wgt_ 가중치 버퍼

acc_ 누산기 (int32) · 지금 타일이 쓰는 엔트리

VTA는 store가 int8만 내보내서 중간 합(int32)을 DRAM에 내릴 수 없다. 그래서 합산 축 k는 칩 안에서 끝내고(출력 고정), 그 바깥에서 입력 고정과 가중치 고정 중 하나를 고른다.

이 시뮬레이터의 단순화: 행 묶음 하나의 입력 엔트리(k 전체)와 출력 단위 하나의 가중치 엔트리(k 전체)가 버퍼에 한꺼번에 들어간다고 가정한다(k를 쪼개지 않음). 또 load와 GEMM을 겹치지 않고 차례로 실행한다. 실제 VTA는 k를 나눠 흘려보내거나(누산기는 칩에 유지), virtual_thread로 load와 계산을 겹칠 수 있다. 겹치기는 시간축 시뮬레이터에서 다룬다.

이상적인 모델: 바로 전 타일과 같은 엔트리가 이미 버퍼에 있으면 다시 읽지 않는다. 실제 TVM 코드는 compute_at을 붙인 루프가 돌 때마다 load를 다시 실행하므로, 같은 설정이라도 트래픽이 더 나올 수 있다 (→ vta_schedule_compare.html).
